# System card · ResultTrail synthetic MVP

**Purpose:** demonstrate preservation, delivery and human review of an independent fictional result copy. It cannot establish source authenticity or declare an election result.

**Flow:** PWA guided checklist, encrypted IndexedDB draft, queued record and optional image → authenticated same-origin intake → durable result version, digest and signed receipt → declared image upload and digest verification → deterministic arithmetic flags → human field comparison and reviewer decision → reporter progress timeline → allowlisted signed export. The checklist confirmations and device-recorded save time are signed with the payload; they are self-attested and the device clock is not independently verified. The local backend uses FastAPI and SQLite; the public website uses a Cloudflare Worker and D1. The offline-image and field-comparison features are hosted-only. Actor and tenant come from the server session. A client role field cannot grant permissions. Every correction creates a new version; previous versions remain in the database. Received results are listed across devices for the same reporter account; unsent drafts remain on the original device.

**Receipt boundary:** Ed25519 signature covers tenant, report ID, version, canonical SHA-256 digest, server receive time and key ID. The browser verifies the signature and digest before displaying “Server received.” The receipt proves this local server accepted those structured bytes under its key; it does not prove that a paper source was authentic, that figures were true, or that delivery was witnessed independently. A local private key compromise would undermine trust in later verification.

**Export boundary:** only the latest reviewer-approved version can be exported. The package allowlist contains fictional election/unit codes and counts, plus the receipt and simulation notice. It excludes reporter/reviewer aliases and raw source note. Its own digest and signature detect package alteration. A standalone verifier checks both package and embedded receipt signature; it cannot independently reconstruct the original full payload from the minimized export.

**Image, comparison and map boundaries:** the hosted reporter form encrypts an optional JPEG, PNG or WebP original up to 750 KB on the device. The signed report version declares its digest, type and size; upload follows receipt verification and can finish for a superseded version. The service stores the bytes, SHA-256 digest and signed image metadata in D1. Authorised reviewers can zoom the image, record per-field human outcomes and notes in an append-only table, and see exact-byte duplicate counts within their tenant. These comparisons do not edit submitted figures, authenticate the paper, or constitute OCR findings. The digest proves byte identity after upload; it cannot establish where or when a photo was taken. The reviewer-only map counts only received synthetic submissions or arithmetic checks. Blank states mean no submitted record with that state, not zero election activity. See [boundary attribution](geodata.md) and [privacy and retention](privacy-and-retention.md).

**Threats and mitigations:** network loss leaves a local queue; replay is idempotent; changed reused IDs conflict; unauthorized roles and tenants are rejected; CSRF token protects cookie-authenticated writes; corrupted IndexedDB ciphertext fails closed; API responses use no-store headers. Browser local storage is not a trusted evidence vault against physical compromise, browser malware, cache eviction or forgotten passphrase. Demo accounts have known passwords. No rate limiting, audit service, HSM, multi-site replication, accessibility certification, penetration test or third-party source attestation is claimed.

**AI status:** an optional Isolation Forest ranking was benchmarked against arithmetic and robust peer baselines using fictional labels. Its 0.0119 recall gain was below the predeclared 0.05 threshold, so it is **off**. A separate evidence-aware ranking simulation reached a 0.05 recall gain at a top-20% reviewer budget, but its generator-conditional bootstrap interval for the gain is 0.0191–0.0714, and it used a simulated OCR mismatch signal and generator-derived labels. It does not meet the independent-data, reviewer-time or decision-accuracy gate, so it is also **off**. Outlier score is never fraud likelihood. See [ranking evaluation](review-ranking-evaluation.json), the earlier [model evaluation](synthetic-evaluation.json), and the data sheet.

**OCR experiment:** pinned Tesseract.js assets run locally and are loaded only on request in a build-flagged prototype. A narrow parser proposes figures from a fictional printed sheet, with per-field accept/dismiss controls. It never changes the generated record code, and it never submits figures by itself. The rendered-sheet holdout produced 480 correct high-confidence suggestions out of 480 proposals, but has no independently photographed sheets or consented usability comparison. The synthetic mismatch probe detected 19 of 20 deliberate entry differences. These numbers do not establish field accuracy; OCR remains **off** in production. See [OCR evaluation](ocr-evaluation.json) and [historical context audit](HISTORICAL_CONTEXT_AUDIT.md).

**Validation:** 5 local Python API tests passed for the original workflow. A local Worker/D1 integration test covers receipt, version-bound image upload, replay, reporter isolation, field-action history and final-decision lock. A browser test restored an encrypted image draft after reload, synced report and image, then saved a reviewer field outcome and used the zoom controls. The hosted Worker accepted a signed report with a declared image and a reviewer field comparison. These checks do not establish real-world accuracy, source authenticity or security certification. Android, screen reader, forced process crash, power failure, 100-user load and external security review are still untested. The prototype should not be used with real election data.
