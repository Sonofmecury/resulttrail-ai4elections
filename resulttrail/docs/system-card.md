# System card · ResultTrail synthetic MVP

**Purpose:** demonstrate preservation, delivery and human review of an independent fictional result copy. It cannot establish source authenticity or declare an election result.

**Flow:** PWA guided checklist, encrypted IndexedDB draft and queue → authenticated same-origin intake → durable result version, digest and signed receipt → optional source image attached after receipt → deterministic arithmetic flags → reviewer decision and reporter progress timeline → allowlisted signed export. The checklist confirmations and device-recorded save time are signed with the payload; they are self-attested and the device clock is not independently verified. The local backend uses FastAPI and SQLite; the public website uses a Cloudflare Worker and D1. The source-image feature is hosted-only. Actor and tenant come from the server session. A client role field cannot grant permissions. Every correction creates a new version; previous versions remain in the database. Received results are listed across devices for the same reporter account; unsent drafts remain on the original device.

**Receipt boundary:** Ed25519 signature covers tenant, report ID, version, canonical SHA-256 digest, server receive time and key ID. The browser verifies the signature and digest before displaying “Server received.” The receipt proves this local server accepted those structured bytes under its key; it does not prove that a paper source was authentic, that figures were true, or that delivery was witnessed independently. A local private key compromise would undermine trust in later verification.

**Export boundary:** only the latest reviewer-approved version can be exported. The package allowlist contains fictional election/unit codes and counts, plus the receipt and simulation notice. It excludes reporter/reviewer aliases and raw source note. Its own digest and signature detect package alteration. A standalone verifier checks both package and embedded receipt signature; it cannot independently reconstruct the original full payload from the minimized export.

**Image and map boundaries:** the hosted service accepts JPEG, PNG or WebP originals up to 750 KB after a version has been received and before a review decision. It stores the bytes, SHA-256 digest and a signature over image metadata in D1. The image is visible only to authorized accounts in the same tenant. The digest proves byte identity after upload; it cannot establish where or when a photo was taken. The reviewer-only map uses state boundaries and counts only received synthetic submissions or arithmetic checks. Blank states mean no submitted record with that state, not zero election activity. See [boundary attribution](geodata.md) and [privacy and retention](privacy-and-retention.md).

**Threats and mitigations:** network loss leaves a local queue; replay is idempotent; changed reused IDs conflict; unauthorized roles and tenants are rejected; CSRF token protects cookie-authenticated writes; corrupted IndexedDB ciphertext fails closed; API responses use no-store headers. Browser local storage is not a trusted evidence vault against physical compromise, browser malware, cache eviction or forgotten passphrase. Demo accounts have known passwords. No rate limiting, audit service, HSM, multi-site replication, accessibility certification, penetration test or third-party source attestation is claimed.

**AI status:** an optional Isolation Forest ranking was benchmarked against arithmetic and robust peer baselines using fictional labels. Its 0.0119 recall gain was below the predeclared 0.05 threshold, so it is **off**. Outlier score is never fraud likelihood. See the evaluation JSON and data sheet.

**Validation:** 5 local API tests passed, including receipt/replay/correction/permissions/export/invalid input and the new checklist and reporter feedback fields. A Chromium browser previously completed sign in, encrypted local save, verified sync, reviewer approval, signed export and standalone verification. An offline browser reload preserved a queued correction, which synced after reconnect. A consistent SQLite backup verified two receipt versions. The hosted Worker smoke test covers login, receipt, replay, geography, source-image upload/download and hash, cross-device listing, review and signed export. Mobile browser layouts were visually inspected before the latest checklist update. Android, screen reader, forced process crash, power failure, 100-user load and external security review are still untested. The prototype should not be used with real election data.
