# Hosted ResultTrail

The synthetic-only website is **https://resulttrail.ng**. The stable [Workers address](https://aegisrelay-app.mukhtarabdulrazaq-18.workers.dev) also serves it. Cloudflare serves the PWA and runs `src/index.ts`; D1 stores accounts, sessions, immutable result versions, source images, reviews and exports. The Ed25519 signing key is a Worker secret. No request reaches the developer laptop.

## Site access

For the hackathon, use the separate `hackathon-observer` and `hackathon-reviewer` accounts. Their verified sign-in details and role instructions are in the private, ignored `../instance/hackathon-access.md` handout. Share that file privately with the intended participants. Each observer chooses a separate device-vault passphrase after signing in.

Two separate initial accounts were provisioned with random passwords. Their private local credential files are:

- `../instance/cloud-remote-reporter-credential.json`
- `../instance/cloud-remote-reviewer-credential.json`

The `instance/` directory is ignored by Git. **Do not publish or commit these files.** A person signs in from any device with their assigned alias and password, then creates a separate passphrase to protect that device's offline queue. Accepted results appear in **Received across devices** when the same reporter account signs in elsewhere. Unsent drafts remain on the device that saved them. Different people should have different accounts. Public self-registration is deliberately disabled; the site owner creates accounts so only invited people can submit or review. The initial `reporter` and `reviewer` accounts are for controlled demonstration.

To create another user, from this `cloud` directory:

```powershell
node scripts/provision.mjs remote observer_a reporter synthetic-team
npx wrangler d1 execute aegisrelay-prod --remote --file ../instance/cloud-remote-observer_a-account.sql
```

This writes a random password to `../instance/cloud-remote-observer_a-credential.json`. Deliver it to that person through a private channel outside this repository. Use `reviewer` as the role only for trusted reviewers. The account SQL contains a salted password hash, not the password. To disable an account, run `npx wrangler d1 execute aegisrelay-prod --remote --command "UPDATE account SET active=0 WHERE alias='observer_a'"` and delete its sessions.

## Deploy and backups

The geographic explorer loads state, LGA and operational ward boundaries from the static assets generated by `../client/scripts/prepare_geodata.py`. The map file sources, licenses and limits are documented in `../docs/geodata.md`. The reporter form uses the same State → LGA → Ward names. `node scripts/seed-hackathon.mjs` idempotently adds the curated 15-state illustrative data set to the hosted service; it requires the private initial account credentials and Pillow to draw three source copies. Keep the handout accounts separate from the seeding accounts.

`npm ci` installs the development tools, `npm run check` checks TypeScript, and `npm run deploy` publishes the Worker and the already built `../client/dist`. Build the client first with `npm ci; npm run build` in `../client`. Database migrations are in `migrations/`; apply them with `npm run migrate:remote` before deploying schema changes. The D1 database ID is bound in `wrangler.jsonc`.

The remote signing key is in the Cloudflare Worker secrets and a private local recovery copy at `../instance/cloud-remote-signing.json`. Back up that file separately and securely: losing it prevents new valid receipts under the same public key; disclosure allows forgeries. Never rotate it silently. `npx wrangler secret list` shows only names, not values.

The initial remote database export was saved privately to `../instance/cloud-remote-backup-20261026.sql`. Make regular backups using `npx wrangler d1 export aegisrelay-prod --remote --output ../instance/BACKUP_NAME.sql`; protect exports because they contain account hashes and report data. D1 Time Travel on the free plan has a seven-day recovery window, which is not a replacement for independent backups.

## Limits and scope

Cloudflare's free Workers allowance is 100,000 requests per day and D1 has a 500 MB maximum database size per free database, with 5 million rows read and 100,000 rows written per day. Above free limits, operations may fail until reset. Static asset requests are free. Source images are stored in D1, capped at 750 KB per version, so this storage plan is suitable only for a small demonstration. The app code is open source; Cloudflare hosting is a proprietary external service. This remains a synthetic research site, not a production election service. It has no real result-form evidence or official integration. More security, privacy, accessibility and load testing is needed before any real-world pilot.
